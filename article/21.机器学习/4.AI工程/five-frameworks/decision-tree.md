- **长任务不漂移** → `planning-with-files`
- **大项目不跑偏** → `GSD`

## 🎯 主决策表(从你的特征出发)

### 关键问题 1:你做的项目类型是什么?

| 项目类型 | 主推 | 理由 |
|---|---|---|
| **Web 应用 / SaaS / 创业项目** | 🟦 gstack | 真实浏览器测试是杀手锏 |
| **复杂后端 / 重构 / 中大型项目** | 🟪 Superpowers | TDD 铁律 + 子代理流程 |
| **企业级 / 团队协作 / 多语言栈** | 🟧 ECC | 全家桶 + AgentShield 安全 |
| **长任务(> 10 步)经常失忆** | 🟩 pwf | 3 文件 + 5 Hook 防漂移 |
| **中大型项目 / 原型快速 / 完整项目跑通** | 🟥 GSD | 上下文隔离 + 多 Agent |
| **Demo / 一次性脚本** | ❌ 都不装 | 装上比写代码还累 |
| **多平台切换(Claude/Codex/Cursor)** | 🟪 Superpowers / 🟧 ECC / 🟩 pwf | 三个都跨多平台 |

### 关键问题 2:你的角色是什么?

| 角色 | 主推 | 理由 |
|---|---|---|
| **独立开发者 / 独立黑客** | 🟦 gstack | 显式指挥,符合 solo 风格 |
| **团队 Tech Lead** | 🟧 ECC | 配置可团队复制 |
| **后端工程师** | 🟪 Superpowers | TDD、子代理契合后端思维 |
| **前端工程师** | 🟦 gstack | 浏览器测试是真痛点 |
| **安全 / DevOps** | 🟧 ECC | AgentShield 解决安全焦虑 |
| **产品经理 / 创业 CEO** | 🟦 gstack | 角色视角贴近团队直觉 |
| **大型项目 owner** | 🟥 GSD | 拆任务 + 并行 + 原子 commit |
| **长跑马拉松型开发者** | 🟩 pwf | 断点续传、跨天接续 |

### 关键问题 3:你最想解决什么问题?

| 痛点 | 主推 | 理由 |
|---|---|---|
| **AI 跳步,直接写代码跑偏** | 🟪 Superpowers | brainstorming 强制先想 |
| **AI 不写测试 / 跳过验证** | 🟪 Superpowers | TDD 铁律是硬约束 |
| **想在不同视角(产品/设计/QA)切换** | 🟦 gstack | `/plan-ceo-review` 等 |
| **新会话失忆,每次重新解释项目** | 🟧 ECC / 🟩 pwf | ECC 三钩 / pwf 三文件 |
| **AI 跑到 50 轮开始胡说,代码质量崩塌** | 🟥 GSD | 上下文隔离治腐烂 |
| **Token 烧太狠,想省钱** | 🟧 ECC | 量化阈值 + 优化配置 |
| **AI 代理本身有安全风险** | 🟧 ECC | AgentShield 1282 测试用例 |
| **想真实点网页、跑 E2E** | 🟦 gstack | `$B` 浏览器底层 |
| **跨平台统一(Claude/Cursor/Codex)** | 🟪 Superpowers / 🟧 ECC / 🟩 pwf | 三个都支持 |
| **需要 git 历史可 bisect / 审计** | 🟥 GSD | 原子 commit 策略 |
| **多项目并行,状态不串** | 🟩 pwf | `.planning/` 隔离 |
| **跑长任务经常中断,下次不知道从哪接** | 🟩 pwf | `/gsd:pause-work` 或 pwf 三文件 |

## 🧠 灵魂问题(比上面更重要)

> 框架的"功能差异"远不如"**你想要什么样的工作方式**"重要。

### 灵魂问题 A:你喜欢"显式管理"还是"放手让它做"?

| 风格 | 你 | 主推 |
|---|---|---|
| **显式管理**:我喜欢主动叫"现在切到 CEO 视角"、"现在审查代码" | 🟦 gstack |
| **放手让它做**:我懒得记命令,希望 AI 自己知道什么时候该 brainstorm、什么时候该测试 | 🟪 Superpowers |
| **既要规范又要灵活**:有流程,但要能跳步 | 🟥 GSD(默认严格,`/gsd:quick` 跳过) |
| **都要**:我需要时显式调用,平时让它自己跑 | 🟧 ECC / 🟩 pwf(混合触发) |

### 灵魂问题 B:你最怕 AI 做什么?

| 恐惧 | 你 | 主推 |
|---|---|---|
| **瞎承诺**:"完成了"但其实没完成 | 🟪 Superpowers(verification-before-completion) |
| **失忆**:聊到一半上下文没了 | 🟧 ECC(三钩记忆)/ 🟩 pwf(三文件) |
| **跑偏**:越改越乱,跑到 50 轮就疯了 | 🟥 GSD(上下文隔离) |
| **失控**:越改越乱,改坏别的地方 | 🟦 gstack(`/freeze` 锁范围) |
| **被夸晕**:奉承型 AI 让我高估自己 | 任何(都没解决,但保持独立判断) |

### 灵魂问题 C:你愿意投入多少学习成本?

| 投入 | 推荐 |
|---|---|
| **5 分钟**(就想加几个有用命令) | 🟦 gstack,先装 `/qa` 和 `/review` |
| **半小时**(想系统了解一个新工作流) | 🟪 Superpowers,跑一遍 5 步流程 |
| **半小时**(想治"AI 跑 50 轮就发疯") | 🟥 GSD,跑完一个 5 阶段项目 |
| **半天**(想用上下文工程思想) | 🟩 pwf,完整跑通一个长任务 |
| **一周**(想沉淀一整套团队配置) | 🟧 ECC,逐步启用 6 大模块 |
| **永远不想学**(只想补全) | Cursor / Copilot,**别装框架** |

### 灵魂问题 D:你跑的任务多长?

| 任务长度 | 推荐 |
|---|---|
| **< 30 分钟**(单文件修改、bug 修复) | 别装,用 Claude Code 默认 |
| **30 分钟 ~ 2 小时**(小功能) | 🟦 gstack(轻量命令) |
| **2 ~ 8 小时**(中等原型) | 🟥 GSD 单独 / 🟩 pwf 单独 |
| **1 ~ 3 天**(长任务,需要接续) | 🟥 GSD + 🟩 pwf |
| **> 1 周**(大型产品) | 🟥 GSD + 🟩 pwf + 🟪 Superpowers |
| **企业级 / 团队** | 全部 + 🟧 ECC 做配置中心 |

## ✅ 决策卡片(三秒选型)

### 卡片 1:装 `gstack` 如果...

```
☐ 我做的是 Web/SaaS,需要真实浏览器测试
☐ 我喜欢显式调用命令切换视角
☐ 我想模拟"团队决策"(CEO/EM/QA/Designer)
☐ 我是独立开发者或小团队
☐ 我想用 $B 底层命令做精细控制
```

**至少 3 项打勾 → 装 gstack**

### 卡片 2:装 `Superpowers` 如果...

```
☐ 我做后端 / 复杂功能,需要严格工程纪律
☐ 我希望 AI 自动遵循 TDD / brainstorm / code review
☐ 我不想记命令,希望 skill 自动触发
☐ 我跨平台用(Claude/Codex/Cursor 都用)
☐ 我重视"先想清楚再动手"的工作流
```

**至少 3 项打勾 → 装 Superpowers**

### 卡片 3:装 `Everything Claude Code` 如果...

```
☐ 我想要"一站式"配置,不想东拼西凑
☐ 我维护大型项目,需要完整覆盖
☐ 我关注 AI 代理安全风险(AgentShield)
☐ 我想学真实生产的最佳实践
☐ 我想用本能(instinct)持续学习
☐ 我有团队,想统一配置
```

**至少 3 项打勾 → 装 ECC**

### 卡片 4:装 `planning-with-files` 如果...

```
☐ 我跑长任务(> 10 步)经常失忆
☐ 我做多文件重构,需要持续追踪
☐ 我经常中断任务,下次想无缝接续
☐ 我同时维护多个项目
☐ 我喜欢极简主义——一个痛点一个解法
```

**至少 3 项打勾 → 装 pwf**

### 卡片 5:装 `GSD` 如果...

```
☐ 我痛恨 AI 聊到 30 轮开始胡说
☐ 我想让 AI 跑完整项目(从需求到部署)
☐ 我需要并行(建模型 + API 同时跑)
☐ 我看重 git 历史的整洁(原子提交)
☐ 我做 SaaS / Web 产品
```

**至少 3 项打勾 → 装 GSD**

## 🚫 反向决策(什么时候不该装)

| 信号 | 结论 |
|---|---|
| 你只是想"补全代码" | 别装,装个 Copilot 就够 |
| 你每个项目 < 1 小时 | 别装,流程成本 > 收益 |
| 你不愿意改变工作流 | 别装,装了也会闲置 |
| 你只想"装上立刻变强" | 别装,工具不会让你变强 |
| 你的项目没有测试基础 | Superpowers / GSD 的 TDD 会让你崩溃 |
| 你不在 Claude Code 生态 | gstack 不适合(它主要靠 Claude Code) |
| **你想试 5 个全部** | ❌ 别试,你会疯。从一个开始,熟练再加 |

## 🔗 组合玩法(进阶)

如果你时间和精力允许,**最强组合**是分工:

```
┌────────────────────────────────────────────────┐
│  GSD  →  拆任务 / 并行执行 / 原子 commit        │
│  pwf  →  持久化记忆 / 断点续传                 │
│  Superpowers  →  流程纪律 / TDD / 子代理审查  │
│  gstack  →  真实浏览器测试 / 角色视角          │
│  ECC  →  配置中心 / AgentShield 安全           │
└────────────────────────────────────────────────┘
```

**最常见三组合**:

1. **GSD + pwf**:拆任务 + 不丢上下文(大项目首选)
2. **Web 创业**:gstack + Superpowers + pwf(全场景覆盖)
3. **企业团队**:ECC + Superpowers + GSD(标准化 + 流程 + 审计)

**但对 90% 的人来说,正确的路径是**:

```
第 1 个月  →  装一个,跑熟
第 2 个月  →  觉得哪里不够,加第二个
第 3 个月  →  沉淀自己的 skill / rule
半年后    →  才考虑 3 件套
```

## 🎁 给决策困难症的最终建议

> **选 Superpowers。**

原因:
- ✅ 规模适中(14 个 skill),不会一上来就被淹没
- ✅ 自动触发,不用记命令,适合新手
- ✅ 流程纪律明显,装上立刻有感觉
- ✅ 跨平台(6 个),未来切换不浪费
- ✅ TDD 铁律一旦习惯,受益终生

**接下来根据需要加**:
- 想要更多"现实世界经验" → 加 ECC
- 想要"真实测试"和"角色视角" → 加 gstack
- 经常跑长任务失忆 → 加 pwf
- 大项目 AI 跑到 50 轮发疯 → 加 GSD

**先去用,再决定。**
