## 基础概念

### 定义

AI Agent 是一个能自主感知环境、做出决策并执行行动的智能程序。

与"输入→输出"式程序不同，Agent 的核心特征是自主性。

|      | 传统程序         | AI Agent           |
|------|--------------|--------------------|
| 行为模式 | 像自动售货机：投币→出货 | 像私人助理：理解需求→自主规划→执行 |
| 决策方式 | 预设规则，固定流程    | 根据目标动态调整策略         |
| 适应能力 | 遇到意外就报错      | 遇到障碍会尝试替代方案        |
| 例子   | 计算器          | Siri / AutoGPT     |

### 核心组件

一个完整的 AI Agent 由 5 个核心模块组成：

```
┌─────────────────────────────────────────┐
│              AI Agent 架构               │
│                                         │
│  ┌───────────┐    ┌───────────────────┐ │
│  │  感知模块  │───→│   大脑（LLM）     │ │
│  │ (Perception)│   │  推理 + 决策中心  │ │
│  └───────────┘    └────────┬──────────┘ │
│                            │            │
│  ┌───────────┐    ┌───────▼──────────┐  │
│  │  记忆模块  │◄──→│   规划模块       │  │
│  │ (Memory)   │    │  (Planning)      │  │
│  └───────────┘    └───────┬──────────┘  │
│                            │            │
│                   ┌────────▼──────────┐  │
│                   │   工具模块        │  │
│                   │  (Tools/Actions)  │  │
│                   └──────────────────┘  │
└─────────────────────────────────────────┘
```

1. 感知模块（Perception）— Agent 的"眼睛和耳朵"。接收用户输入、环境变化、外部信号。例：接收一条用户消息、读取一个文件、监听 API 回调。
2. 大脑（LLM）— Agent 的"思考中枢"。理解意图、推理分析、生成方案。例：GPT-4、Claude、通义千问。
3. 记忆模块（Memory）— Agent 的"笔记本"。
   - 短期记忆：当前对话上下文（工作记忆）。
   - 长期记忆：持久化存储的知识和经验（长期知识库）。例：向量数据库存储的历史交互记录。
4. 规划模块（Planning）— Agent 的"策略师"。将复杂目标拆解为可执行步骤。常见策略：ReAct（推理+行动交替）、Chain-of-Thought（思维链）。例："帮我部署网站" → 选服务器→写代码→配置域名→上线。
5. 工具模块（Tools/Actions）— Agent 的"手脚"。搜索引擎、代码执行器、文件读写、API 调用。例：调用天气 API 查询、执行 Python 代码、操作数据库。

## 工作模式


| 模式 | 核心机制 | 适用场景 | 优点 | 缺点 | 成本/延迟 |
|---|---|---|---|---|---|
| ReAct ⭐最主流 | Thought→Action→Observation 循环。模型边思考边执行，根据上一步结果决定下一步 | 探索性强、动态变化、步骤无法提前确定的任务（客服排查、信息搜索、代码调试）| 灵活性高、适应性强、推理过程可解释 | 多轮调用导致延迟高、成本增加；长任务易丢失目标；对工具报错缺乏免疫力 | 成本中高/延迟中高 |
| CoT 思维链 | 一步步推理不动手。问题→推理1→推理2→答案 | 数学推理、逻辑分析、多步推导 | 推理过程清晰 | 不调用工具，无法与外部环境交互 | 成本低/延迟低 |
| ToT 思维树 | 生成多方案→评估→选最佳。多条路径并行探索 | 创意生成、复杂决策、博弈问题 | 能跳出局部最优 | 生成成本高，评估难度大 | 成本高/延迟高 |
| Reflection 反思 | 生成→批评→改进→再批评循环。Reflector 批评输出，Generator 据此修订，至质量达标 | 质量敏感型任务（内容创作、代码生成、报告撰写）| 显著降低幻觉、自我纠错提升质量、适合从失败中学习 | 每轮多一次 LLM 调用，Token 成本翻倍；延迟高 | 成本高/延迟高 |
| Plan-and-Execute | 先全局规划后分步执行。Planner 生成步骤清单，Executor 逐步执行，Replanner 根据结果动态调整 | 流程长、步骤稳定、子任务依赖性高、需审计的任务（标准化巡检、常规故障排查、高风险操作）| 稳定性强、不易遗漏步骤、计划可审查、执行成本可控 | 初始计划可能失准；应对突发变化灵活性差，依赖 Replanner 纠偏 | 成本中/延迟中低 |
| Function Calling | 模型直接输出结构化参数调用 API，无显式推理链 | 单步或简单顺序任务（翻译、摘要、分类、单次检索）| 实现简单、延迟极低、成本最省 | 无法处理多步推理复杂任务 | 成本低/延迟低 |

选型建议：
- 简单任务优先用 Function Calling。
- 长流程需稳定首选 Plan-and-Execute，配 Replanner 动态纠偏。
- 探索性任务用 ReAct，设最大步数防死循环。
- 高质量要求在上述基础上叠加 Reflection，需接受成本翻倍。
- 生产实践多为混合模式：Plan-and-Execute 全局统筹，子任务内部用 ReAct 执行，关键节点加 Reflection 质检。


实际开发中模式经常组合，比如 ReAct 决策 + 多 Agent 协作 + Ecomode 执行。选择取决于任务复杂度、成本和精度要求。

### 按决策方式（Agent 怎么"想"）

以下是 LangChain 中实现这 6 种决策方式的代码案例：

```python
from langchain.agents import create_agent
from langchain_core.tools import tool

# ---------- 1. ReAct（create_agent 默认就是 ReAct）----------
# Agent 边推理边调工具，根据工具结果决定下一步

@tool
def search_weather(city: str) -> str:
    """查询城市天气"""
    return f"{city}：晴，25°C"

react_agent = create_agent(
    model=model_openai,
    tools=[search_weather],
    system_prompt="你是天气助手，根据需要调用工具查询天气。",
    max_iterations=5,  # 防死循环
)
result = react_agent.invoke({
    "messages": [{"role": "user", "content": "北京天气怎么样？"}]
})


# ---------- 2. CoT 思维链（不调工具，靠模型推理）----------
# 用带推理能力的模型 + Prompt 引导，不走 Agent 循环

from langchain_core.prompts import ChatPromptTemplate

cot_prompt = ChatPromptTemplate.from_messages([
    ("system", "一步步推理后再给答案。"),
    ("user", "{question}"),
])
cot_chain = cot_prompt | model_openai
result = cot_chain.invoke({"question": "一个水池有两个进水管..."})  # 数学推理


# ---------- 3. ToT 思维树（无内置，需自己组装）----------
# 生成多个候选方案 → 评分 → 选最优

@tool
def generate_options(problem: str) -> list[str]:
    """生成多个候选方案"""
    # 实际是多次调用模型
    return ["方案A", "方案B", "方案C"]

@tool
def evaluate_option(option: str) -> float:
    """对方案评分"""
    return 0.85

# 自行循环：generate → evaluate → 取最高分
# LangChain 无内置 ToT Agent


# ---------- 4. Reflection 反思（用中间件在 after 钩子批评-修订）----------
# 自定义中间件，agent 执行后让 Reflector 批评，Generator 修订

from langchain.agents.middleware import AgentMiddleware

class ReflectionMiddleware(AgentMiddleware):
    async def after_agent(self, state, runtime):
        output = state["messages"][-1].content
        # 让模型批评自己的输出
        critique = await model_openai.ainvoke(
            f"批评这段回答的不足：{output}"
        )
        # 根据批评修订
        revised = await model_openai.ainvoke(
            f"根据批评修订：{output}\n批评：{critique.content}"
        )
        state["messages"][-1].content = revised.content
        return state

reflect_agent = create_agent(
    model=model_openai,
    tools=[],
    system_prompt="你是写作助手。",
    middleware=[ReflectionMiddleware()],
)


# ---------- 5. Plan-and-Execute（无内置完整版，自己组装三部分）----------
# Planner 规划 → Executor 逐步执行 → Replanner 动态纠偏

@tool
def make_plan(task: str) -> list[str]:
    """生成步骤清单"""
    return ["步骤1: 收集资料", "步骤2: 分析", "步骤3: 生成报告"]

@tool
def execute_step(step: str) -> str:
    """执行单步（内部可跑一个 ReAct agent）"""
    return f"{step} 已完成"

plan = make_plan.invoke({"task": "写市场分析报告"})
for step in plan:
    result = execute_step.invoke({"step": step})
    # Replanner：根据 result 决定继续、跳过或改 plan
    # 实际用一次 LLM 调用判断


# ---------- 6. Function Calling（绑工具直接调，不走 Agent 循环）----------
# 模型原生 function calling，单步任务

bound_model = model_openai.bind_tools([search_weather])
response = bound_model.invoke("北京天气怎么样？")
# response.tool_calls 直接拿到结构化参数，单次调用
```


### 按架构模式（Agent 怎么"组织"）

| 模式 | 结构 | 案例 |
|---|---|---|
| 单 Agent | 用户 ↔ 一个 Agent | 简单问答、单一任务处理 |
| Pipeline 流水线 | A→B→C，任务按顺序在 Agent 间流转 | Dify |
| Hierarchical 分层 | 调度者→执行者们。管理者 Agent 分配协调，其他 Agent 各司其职 | AutoGen、CrewAI hierarchical 模式 |
| Discussion 讨论 | A↔B↔C 互相质疑。多 Agent 通过对话讨论解决问题 | AutoGen 群聊模式 |
| Swarm 群体 | 并行执行→合并。大量简单 Agent 并行工作，涌现集体智能 | OpenAI Swarm |
| Multi-Agent 协作 | 多角色分工协作。多个 Agent 各司其职，通过通信协议交换信息协同完成任务 | MetaGPT、CrewAI |
| Routing 路由分发 | 先分类后分发。对用户输入做意图识别，转交给最合适的专精模型或 Agent | 客服系统按问题类型分发 |

### 按执行模式（Agent 怎么"跑"）

| 模式            | 一句话           | 适用      |
|---------------|---------------|---------|
| Autopilot 全自动 | 给目标，自己搞定      | 确定性重复任务 |
| Copilot 人机协作  | 人拍板，AI 干活      | 日常开发辅助  |
| Ultrapilot 并行 | 3-5 个同时干      | 大规模任务   |
| Ecomode 经济    | 简单用小模型，复杂用大模型 | 省成本     |

### 按记忆模式（Agent 怎么"记"）

| 模式   | 特点           |
|------|--------------|
| 无状态  | 用完即忘，适合一次性任务 |
| 短期记忆 | 记住当前对话，关了就忘  |
| 长期记忆 | 向量库持久化，跨会话记住 |

1. 从单 Agent 到多 Agent 协同：行业基线从"一个 Agent 调一个模型"演进为"多 Agent 协同 + 多模型智能路由"。竞争焦点从开发工具属性转向全生命周期的生产级治理能力（权限、审计、可观测、成本管控）。

案例2：最简 Agent。理解 Agent 的基本循环——感知→思考→行动。这个 Agent 已包含感知（接收输入）和思考（LLM 推理），还没有记忆和工具。

```python
from openai import OpenAI

client = OpenAI(api_key="你的API密钥")

def simple_agent(user_input: str) -> str:
    """最简单的 Agent：接收输入 → LLM 思考 → 返回输出"""

    system_prompt = """你是一个有帮助的AI助手。
    回答问题时，先分析用户需求，再给出清晰的结构化回答。"""

    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_input}
        ]
    )

    return response.choices[0].message.content

# 测试
```

案例3：带记忆的 Agent。`self.messages` 是 Agent 的短期记忆。每次对话带上完整历史，LLM 就能"记住"之前的内容。

```python
from openai import OpenAI
client = OpenAI(api_key="你的API密钥")

class MemoryAgent:
  def __init__(self):
    # 系统内存保存上下文
    self.messages = [
      {"role": "system", "content": "你是一个有帮助的AI助手，能记住之前的对话内容。"}
    ]

  def chat(self, user_input: str) -> str:
    # 感知：记录用户输入
    self.messages.append({"role": "user", "content": user_input})

    # 思考：LLM 推理（自动包含历史记忆）
    response = client.chat.completions.create(
        model="zhipu/glm-4-flash",
        messages=self.messages
    )

    assistant_message = response.choices[0].message.content

    # 记忆：保存助手回复
    self.messages.append({"role": "assistant", "content": assistant_message})

    return assistant_message

  def show_memory(self):
    """查看 Agent 的记忆"""
    print(f"记忆中有 {len(self.messages)} 条消息")
    for msg in self.messages[1:]:  # 跳过 system prompt
      role = "👤用户" if msg["role"] == "user" else "🤖助手"
      print(f"{role}: {msg['content'][:50]}...")

# 测试
agent = MemoryAgent()
print(agent.chat("我叫小明，我在学Python"))
print(agent.chat("我叫什么名字？"))  # Agent 能记住
agent.show_memory()
```

案例4：带工具的 Agent。让 Agent 从"只会说话"变成"能做事"。这是 ReAct 模式的核心——LLM 自主决定何时调用工具、调用哪个工具、如何使用工具结果。

```python
import json
from openai import OpenAI

client = OpenAI(api_key="你的key",
                base_url="https://platform.aitools.cfd/api/v1")

# 定义工具函数
def get_weather(city: str) -> str:
  """模拟天气查询（实际项目中调用真实API）"""
  weather_data = {
    "北京": "晴天，25°C",
    "上海": "多云，22°C",
    "深圳": "小雨，28°C"
  }
  return weather_data.get(city, f"{city}：暂无天气数据")

def calculate(expression: str) -> str:
  """安全计算数学表达式"""
  try:
    allowed = set("0123456789+-*/.() ")
    if all(c in allowed for c in expression):
      return str(eval(expression))
    return "不安全的表达式"
  except:
    return "计算错误"

# 工具注册表
tools = [
  {
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "查询指定城市的天气",
      "parameters": {
        "type": "object",
        "properties": {
          "city": {"type": "string", "description": "城市名称"}
        },
        "required": ["city"]
      }
    }
  },
  {
    "type": "function",
    "function": {
      "name": "calculate",
      "description": "计算数学表达式",
      "parameters": {
        "type": "object",
        "properties": {
          "expression": {"type": "string", "description": "数学表达式"}
        },
        "required": ["expression"]
      }
    }
  }
]

# 工具执行映射
tool_map = {
  "get_weather": get_weather,
  "calculate": calculate
}

class ToolAgent:
  def __init__(self):
    self.messages = [
      {"role": "system", "content": "你是一个能查询天气和做计算的AI助手。根据用户需求选择合适的工具。"}
    ]

  def chat(self, user_input: str) -> str:
    self.messages.append({"role": "user", "content": user_input})

    # 第一步：LLM 决定是否需要调用工具
    response = client.chat.completions.create(
        model="openai/gpt-oss-20b",
        messages=self.messages,
        tools=tools
    )

    message = response.choices[0].message

    # 第二步：如果 LLM 决定调用工具
    if message.tool_calls:
      for tool_call in message.tool_calls:
        func_name = tool_call.function.name
        func_args = json.loads(tool_call.function.arguments)

        print(f"  🔧 调用工具: {func_name}({func_args})")

        # 执行工具：展开字典为关键字参数
        result = tool_map[func_name](**func_args)
        print(f"  📋 工具结果: {result}")

        # 把工具结果告诉 LLM
        self.messages.append(message)
        self.messages.append({
          "role": "tool",
          "tool_call_id": tool_call.id,
          "content": result
        })

      # 第三步：LLM 基于工具结果生成最终回答
      final_response = client.chat.completions.create(
          model="openai/gpt-oss-20b",
          messages=self.messages
      )
      final_message = final_response.choices[0].message.content
      self.messages.append({"role": "assistant", "content": final_message})
      return final_message

    # 不需要工具，直接回答
    self.messages.append({"role": "assistant", "content": message.content})
    return message.content

# 测试
agent = ToolAgent()
print(agent.chat("北京今天天气怎么样？"))
print("---")
print(agent.chat("帮我算一下 (123 + 456) * 2"))
```

案例5：多步骤规划 Agent。本质是提示词工程——Agent 自主拆解复杂任务分步执行。

```python
from openai import OpenAI

client = OpenAI(api_key="你的key",
                base_url="https://platform.aitools.cfd/api/v1")

class PlanningAgent:
  """能自主规划多步骤任务的 Agent"""

  def __init__(self):
    self.messages = [
      {"role": "system", "content": """你是一个智能规划助手。
当收到复杂任务时，你会：
1. 先制定执行计划（列出步骤）
2. 逐步执行每个步骤
3. 每步完成后评估结果
4. 如有偏差，调整计划

请用以下格式输出计划：
📋 计划：
1. [步骤1]
2. [步骤2]
...

然后逐步执行。"""}
    ]
    self.max_iterations = 5  # 防止无限循环

  def run(self, task: str) -> str:
    self.messages.append({"role": "user", "content": task})

    for i in range(self.max_iterations):
      response = client.chat.completions.create(
          model="openai/gpt-oss-20b",
          messages=self.messages
      )

      reply = response.choices[0].message.content
      self.messages.append({"role": "assistant", "content": reply})

      print(f"\n--- 迭代 {i+1} ---")
      print(reply)

      # 检查是否完成
      check = client.chat.completions.create(
          model="openai/gpt-oss-20b",
          messages=self.messages + [
            {"role": "user", "content": "任务是否已完成？只回答'是'或'否'"}
          ]
      )

      if check.choices[0].message.content.strip().startswith("是"):
        print("\n✅ 任务完成！")
        return reply

      # 继续执行
      self.messages.append({"role": "user", "content": "请继续执行下一步。"})

    return "⚠️ 达到最大迭代次数"

# 测试
agent = PlanningAgent()
agent.run("帮我分析学习Python的完整路线图，包括每个阶段的学习重点和时间安排")
```

> 注：案例5 用单轮问答判断"任务是否完成"可靠性低。生产环境应改用结构化输出或独立校验器。

### 扩展能力

构建 AI Agent 建议按顺序配置的 5 个核心工具，系统性解决安全、成本与调试痛点：

1. 隐私（密钥管理）：用 direnv 配合密钥管理器（如 1Password CLI），基于项目自动加载/卸载环境变量，API 密钥等凭证永不明文存盘，防止密钥泄露。
2. 成本与路由（模型代理）：用 litellm 或 Portkey 代理所有模型供应商调用。实现响应缓存省账单、遇限流自动降级、设预算护栏防意外开销、智能路由到性价比最优的模型。
3. 可复现性（依赖与上下文管理）：用 uv 锁定精确依赖。每次评估套件（eval suite）通过后做一次 Git 提交，提交信息记录模型版本和通过率，确保任何历史运行可精确复现和追溯。
4. 可见性与调试（流量监控）：在 Agent 的所有 LLM 调用前部署 mitmproxy。实时窥探 Agent 与模型的完整对话、实际 token 成本，及时发现响应中的意外指令或 Prompt 注入攻击。
5. 评估（标准化测试框架）：用 inspect-ai 框架系统化评估 Agent。提供可重复、可比较的量化分数，包含对高风险行为的预设测试，评估结果比自写测试工具更具可信度和可复现性。
