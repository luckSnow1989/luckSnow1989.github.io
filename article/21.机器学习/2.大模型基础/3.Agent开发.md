## 基础概念

### 1.1 定义

AI Agent（人工智能代理）是一个能够自主感知环境、做出决策并执行行动的智能程序。

与传统的"输入→输出"式程序不同，Agent 拥有一个核心特征：自主性。

用一个生活类比来理解：

|      | 传统程序         | AI Agent           |
|------|--------------|--------------------|
| 行为模式 | 像自动售货机：投币→出货 | 像私人助理：理解需求→自主规划→执行 |
| 决策方式 | 预设规则，固定流程    | 根据目标动态调整策略         |
| 适应能力 | 遇到意外就报错      | 遇到障碍会尝试替代方案        |
| 例子   | 计算器          | Siri / AutoGPT     |

### 1.2 AI Agent 的核心组件

一个完整的 AI Agent 由 5 个核心模块 组成：

```
┌─────────────────────────────────────────┐
│              AI Agent 架构               │
│                                         │
│  ┌───────────┐    ┌───────────────────┐ │
│  │  感知模块  │───→│   大脑（LLM）     │ │
│  │ (Perception)│   │  推理 + 决策中心  │ │
│  └───────────┘    └────────┬──────────┘ │
│                            │            │
│  ┌───────────┐    ┌───────▼──────────┐  │
│  │  记忆模块  │◄──→│   规划模块       │  │
│  │ (Memory)   │    │  (Planning)      │  │
│  └───────────┘    └───────┬──────────┘  │
│                            │            │
│                   ┌────────▼──────────┐  │
│                   │   工具模块        │  │
│                   │  (Tools/Actions)  │  │
│                   └──────────────────┘  │
└─────────────────────────────────────────┘
```

1. 感知模块（Perception） — Agent 的"眼睛和耳朵"
   - 接收用户输入、环境变化、外部信号
   - 例：接收一条用户消息、读取一个文件、监听 API 回调
2. 大脑（LLM — 大语言模型） — Agent 的"思考中枢"
   - 理解意图、推理分析、生成方案
   - 例：GPT-4、Claude、通义千问等大模型
3. 记忆模块（Memory） — Agent 的"笔记本"
   - 短期记忆：当前对话上下文（类似工作记忆）
   - 长期记忆：持久化存储的知识和经验（类似长期知识库）
   - 例：向量数据库存储的历史交互记录
4. 规划模块（Planning） — Agent 的"策略师"
   - 将复杂目标拆解为可执行步骤
   - 常见策略：ReAct（推理+行动交替）、Chain-of-Thought（思维链）
   - 例："帮我部署网站" → 拆分为：选服务器→写代码→配置域名→上线
5.  工具模块（Tools/Actions） — Agent 的"手脚"
   - 搜索引擎、代码执行器、文件读写、API 调用等
   - 例：调用天气 API 查询、执行 Python 代码、操作数据库

## 工作模式

AI Agent 根据不同的决策方式、架构设计和协作方式，可以分为以下几大类模式：

💡 实际开发中模式经常组合，比如：ReAct决策 + 多Agent协作 + Ecomode执行。选择取决于任务复杂度、成本和精度要求。

一、决策方式（Agent 怎么"想"）

| 模式            | 一句话          | 流程            | 案例                                |
|---------------|--------------|---------------|-----------------------------------|
| ReAct ⭐最主流    | 想→做→看→想→做... | 推理→行动→观察→循环   | LangChain ReAct Agent、Claude Code |
| CoT 思维链       | 一步步想，不动手     | 问题→推理1→推理2→答案 | 适用场景 ：数学推理、逻辑分析、多步推导              |
| ToT 思维树       | 多条路选最优       | 生成多方案→评估→选最佳  | 适用场景 ：创意生成、复杂决策、博弈问题              |
| Reflection 反思 | 自己改自己        | 生成→批评→改进→再批评  | 代表实现 ：Reflexion、Self-Refine       |

二、架构模式（Agent 怎么"组织"）

| 模式              | 一句话       | 结构           | 案例                                                                                      |
|-----------------|-----------|--------------|-----------------------------------------------------------------------------------------|
| 单Agent          | 一个人干所有事   | 用户 ↔ 一个Agent | 适用场景 ：简单问答、单一任务处理                                                                       |
| Pipeline 流水线    | 一个接一个干    | A→B→C        | 任务按顺序在 Agent 间流转，像流水线，例如dify                                                            |
| Hierarchical 分层 | 老板分配，员工干活 | 调度者→执行者们     | 特点 ：一个"管理者"Agent 负责任务分配和协调，其他 Agent 各司其职。     <br/>代表 ：AutoGen、CrewAI 的 hierarchical 模式 |
| Discussion 讨论   | 开会讨论出结论   | A↔B↔C 互相质疑   | 特点 ：多个 Agent 通过对话讨论来解决问题，互相质疑和完善。 <br/>      代表 ：AutoGen 的群聊模式                          |
| Swarm 群体        | 各干各的，汇总结果 | 并行执行→合并      | 特点 ：大量简单 Agent 并行工作，涌现出集体智能。<br/> 代表 ：OpenAI Swarm、Oh My Claude Code 的 Swarm 模式         |

三、执行模式（Agent 怎么"跑"）

| 模式            | 一句话           | 适用      |
|---------------|---------------|---------|
| Autopilot 全自动 | 给目标，自己搞定      | 确定性重复任务 |
| Copilot 人机协作  | 人拍板，AI干活      | 日常开发辅助  |
| Ultrapilot 并行 | 3-5个同时干，快     | 大规模任务   |
| Ecomode 经济    | 简单用小模型，复杂用大模型 | 省成本     |

四、记忆模式（Agent 怎么"记"）

| 模式   | 特点           |
|------|--------------|
| 无状态  | 用完即忘，适合一次性任务 |
| 短期记忆 | 记住当前对话，关了就忘  |
| 长期记忆 | 向量库持久化，跨会话记住 |

```python
案例2：最简单的 Agent
目标：理解 Agent 的基本循环 — "感知→思考→行动"
关键理解：这个"最简 Agent"已经包含了感知（接收输入）和思考（LLM推理），只是还没有记忆和工具。

from openai import OpenAI

client = OpenAI(api_key="你的API密钥")

def simple_agent(user_input: str) -> str:
    """最简单的 Agent：接收输入 → LLM 思考 → 返回输出"""
    
    system_prompt = """你是一个有帮助的AI助手。
    回答问题时，先分析用户需求，再给出清晰的结构化回答。"""
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_input}
        ]
    )
    
    return response.choices[0].message.content

# 测试

案例3：添加记忆的 Agent
目标：让 Agent 能记住之前的对话
关键理解：`self.messages` 就是 Agent 的短期记忆。每次对话都带上完整历史，LLM 就能"记住"之前的内容。

from openai import OpenAI
client = OpenAI(api_key="你的API密钥")

class MemoryAgent:
  def __init__(self):
    # 定义系统提示器，用于初始化记忆
    # 注意：这里只是使用系统内存保存上下文。
    self.messages = [
      {"role": "system", "content": "你是一个有帮助的AI助手，能记住之前的对话内容。"}
    ]

  def chat(self, user_input: str) -> str:
    # 感知：记录用户输入
    self.messages.append({"role": "user", "content": user_input})

    # 思考：LLM 推理（自动包含历史记忆）
    response = client.chat.completions.create(
        model="zhipu/glm-4-flash",
        messages=self.messages
    )

    assistant_message = response.choices[0].message.content

    # 记忆：保存助手回复
    self.messages.append({"role": "assistant", "content": assistant_message})

    return assistant_message

  def show_memory(self):
    """查看 Agent 的记忆"""
    print(f"记忆中有 {len(self.messages)} 条消息")
    for msg in self.messages[1:]:  # 跳过 system prompt
      role = "👤用户" if msg["role"] == "user" else "🤖助手"
      print(f"{role}: {msg['content'][:50]}...")

# 测试
agent = MemoryAgent()
print(agent.chat("我叫小明，我在学Python"))
print(agent.chat("我叫什么名字？"))  # Agent 能记住！
agent.show_memory()



案例4：带工具的 Agent
目标：让 Agent 能调用外部工具，从"只会说话"变成"能做事"
关键理解：这就是 ReAct 模式 的核心 — LLM 自主决定何时调用工具、调用哪个工具、如何使用工具结果。

import json
from openai import OpenAI

client = OpenAI(api_key="sk-31132f3d71114bc3bd904ea90e117982",
                base_url="https://platform.aitools.cfd/api/v1")
# 定义工具函数
def get_weather(city: str) -> str:
  """模拟天气查询（实际项目中调用真实API）"""
  weather_data = {
    "北京": "晴天，25°C",
    "上海": "多云，22°C",
    "深圳": "小雨，28°C"
  }
  return weather_data.get(city, f"{city}：暂无天气数据")

def calculate(expression: str) -> str:
  """安全计算数学表达式"""
  try:
    allowed = set("0123456789+-*/.() ")
    if all(c in allowed for c in expression):
      return str(eval(expression))
    return "不安全的表达式"
  except:
    return "计算错误"

# 工具注册表
tools = [
  {
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "查询指定城市的天气",
      "parameters": {
        "type": "object",
        "properties": {
          "city": {"type": "string", "description": "城市名称"}
        },
        "required": ["city"]
      }
    }
  },
  {
    "type": "function",
    "function": {
      "name": "calculate",
      "description": "计算数学表达式",
      "parameters": {
        "type": "object",
        "properties": {
          "expression": {"type": "string", "description": "数学表达式"}
        },
        "required": ["expression"]
      }
    }
  }
]

# 工具执行映射
tool_map = {
  "get_weather": get_weather,
  "calculate": calculate
}

class ToolAgent:
  def __init__(self):
    self.messages = [
      {"role": "system", "content": "你是一个能查询天气和做计算的AI助手。根据用户需求选择合适的工具。"}
    ]

  def chat(self, user_input: str) -> str:
    self.messages.append({"role": "user", "content": user_input})

    # 第一步：LLM 决定是否需要调用工具
    response = client.chat.completions.create(
        model="openai/gpt-oss-20b",
        messages=self.messages,
        tools=tools
    )

    message = response.choices[0].message

    # 第二步：如果 LLM 决定调用工具
    if message.tool_calls:
      for tool_call in message.tool_calls:
        func_name = tool_call.function.name
        func_args = json.loads(tool_call.function.arguments)

        print(f"  🔧 调用工具: {func_name}({func_args})")

        # 执行工具（使用 ** 展开字典为关键字参数）
        result = tool_map[func_name](**func_args)
        print(f"  📋 工具结果: {result}")

        # 把工具结果告诉 LLM
        self.messages.append(message)
        self.messages.append({
          "role": "tool",
          "tool_call_id": tool_call.id,
          "content": result
        })

      # 第三步：LLM 基于工具结果生成最终回答
      final_response = client.chat.completions.create(
          model="openai/gpt-oss-20b",
          messages=self.messages
      )
      final_message = final_response.choices[0].message.content
      self.messages.append({"role": "assistant", "content": final_message})
      return final_message

    # 不需要工具，直接回答
    self.messages.append({"role": "assistant", "content": message.content})
    return message.content

# 测试
agent = ToolAgent()
print(agent.chat("北京今天天气怎么样？"))
print("---")
print(agent.chat("帮我算一下 (123 + 456) * 2"))



案例5：多步骤规划 Agent
目标：Agent 能自主拆解复杂任务，分步执行
本质：提示词工程

from openai import OpenAI

client = OpenAI(api_key="sk-31132f3d71114bc3bd904ea90e117982",
                base_url="https://platform.aitools.cfd/api/v1")

class PlanningAgent:
  """能自主规划多步骤任务的 Agent"""

  def __init__(self):
    self.messages = [
      {"role": "system", "content": """你是一个智能规划助手。
当收到复杂任务时，你会：
1. 先制定执行计划（列出步骤）
2. 逐步执行每个步骤
3. 每步完成后评估结果
4. 如有偏差，调整计划

请用以下格式输出计划：
📋 计划：
1. [步骤1]
2. [步骤2]
...

然后逐步执行。"""}
    ]
    self.max_iterations = 5  # 防止无限循环

  def run(self, task: str) -> str:
    self.messages.append({"role": "user", "content": task})

    for i in range(self.max_iterations):
      response = client.chat.completions.create(
          model="openai/gpt-oss-20b",
          messages=self.messages
      )

      reply = response.choices[0].message.content
      self.messages.append({"role": "assistant", "content": reply})

      print(f"\n--- 迭代 {i+1} ---")
      print(reply)

      # 检查是否完成
      check = client.chat.completions.create(
          model="openai/gpt-oss-20b",
          messages=self.messages + [
            {"role": "user", "content": "任务是否已完成？只回答'是'或'否'"}
          ]
      )

      if check.choices[0].message.content.strip().startswith("是"):
        print("\n✅ 任务完成！")
        return reply

      # 继续执行
      self.messages.append({"role": "user", "content": "请继续执行下一步。"})

    return "⚠️ 达到最大迭代次数"

# 测试
agent = PlanningAgent()
agent.run("帮我分析学习Python的完整路线图，包括每个阶段的学习重点和时间安排")
```

```python
    max_iterations=5,  # 最多5轮
    early_stopping_method="generate"  # 超限后生成最终回答
)

# 技巧4：添加重试机制
import time
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(stop=stop_after_attempt(3), wait=wait_exponential(min=1, max=10))
def call_llm_with_retry(messages):
    return client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages
    )
```

### 2.核心组件

#### 2.1.模型

大型语言模型（LLM）是强大的 AI 工具，能够像人类一样解释和生成文本。它们功能多样，可以撰写内容、翻译语言、总结和回答问题，而无需针对每个任务进行专门训练。

除了文本生成，许多模型还支持：
1. 工具调用 - 调用外部工具（如数据库查询或 API 调用）并在其响应中使用结果。
2. 结构化输出 - 模型响应被限制为遵循定义的格式。
3. 多模态 - 处理和返回除文本之外的数据，例如图像、音频和视频。
4. 推理 - 模型执行多步推理以得出结论。

langchain提供：动态模型、工具调用、输出格式化、多模态、提示缓存、限流、URL代理、日志概率、token用量、
调用配置（使用langsmith监控调试、日志监控、资源使用等）

#### 2.2.消息

消息包括输入与输出，消息是包含以下内容的对象：
1. 角色 - 识别消息类型（例如 system、user）
2. 内容 - 表示消息的实际内容（如文本、图像、音频、文档等）
3. 元数据 - 可选字段，如响应信息、消息 ID 和令牌使用情况

#### 2.3.工具

工具是langchain调用并执行操作的组件，工作流程：
1. 通过模型明确的输入和输出。
2. langchain工具封装了一个可调用函数及其输入模式，这些可以传递给兼容的聊天模型，允许模型决定是否调用工具以及使用哪些参数。
3. 在这些场景中，工具调用使模型能够生成符合指定输入模式的请求。


访问上下文：工具可以通过 ToolRuntime 参数访问运行时信息
1. 上下文：通过 runtime.context 访问不可变配置和上下文数据，如用户 ID、会话详细信息或应用程序特定配置。
2. 内存（存储）：使用存储跨对话访问持久数据。存储通过 runtime.store 访问，允许您保存和检索用户特定或应用程序特定数据。
3. 流写入器：使用 runtime.stream_writer 在工具执行时流式传输自定义更新。这对于向用户提供有关工具正在做什么的实时反馈非常有用。

#### 2.4.记忆

记忆上下文，包括内存、Redis、数据库等。

#### 2.5.流式

LangChain 流式传输可能实现的功能：
1. 流式传输 agent 进度 — 在每个 agent 步骤之后获取状态更新。
2. 流式传输 LLM Tokens — 在语言模型生成 token 时进行流式传输。
3. 流式传输自定义更新 — 发送用户定义的信号（例如，"已获取 10/100 条记录"）。
4. 流式传输多种模式 — 从 updates (agent 进度)、messages (LLM token + 元数据) 或 custom (任意用户数据) 中选择。

#### 2.6.中间件

1. 监控：使用日志、分析和调试跟踪代理行为
2. 修改：转换提示、工具选择和输出格式
3. 控制：添加重试、回退和提前终止逻辑
4. 强制执行：应用速率限制、防护栏和 PII 检测

langchain内置很多中间件。
1. 总结：在接近令牌限制时自动总结对话历史。SummarizationMiddleware
2. 人工干预：在工具调用执行之前，暂停代理执行，以进行人工批准、编辑或拒绝。
3. Anthropic 提示缓存：通过 Anthropic 模型缓存重复的提示前缀来降低成本。
4. 模型调用限制：限制模型调用次数，以防止无限循环或过高成本。
5. 工具调用限制：限制对特定工具或所有工具的调用次数。
6. 模型回退：当主模型失败时，自动回退到备用模型。
7. PII 检测：检测和处理对话中的个人身份信息。
8. 规划：为复杂的、多步骤任务添加待办事项列表管理功能。
9. LLM 工具选择器：在调用主模型之前，使用 LLM 智能选择相关工具。
10. 工具重试：自动重试失败的工具调用，并可配置指数退避。
11. LLM 工具模拟器：使用 LLM 模拟工具执行进行测试，用 AI 生成的响应替换实际的工具调用。
12. 上下文编辑：通过修剪、总结或清除工具使用来管理对话上下文。


自定义中间件：通过实现代理执行流程中特定点的钩子来构建自定义中间件。方式如下：
1. 基于装饰器 - 适用于单钩子中间件，快速简单
2. 基于类 - 适用于具有多个钩子的复杂中间件，功能更强大

#### 2.7.结构化输出

响应格式：控制代理如何返回结构化数据
1. ToolStrategy[StructuredResponseT]：使用工具调用进行结构化输出
2. ProviderStrategy[StructuredResponseT]：使用提供商原生结构化输出
3. type[StructuredResponseT]：架构类型 - 根据模型能力自动选择最佳策略
4. None：无结构化输出

### 3.最佳实践

#### 3.1.安全防护
通过在代理执行的关键点验证和过滤内容，帮助你构建安全、合规的 AI 应用程序。 常见用例包括：
1. 防止 PII 泄漏。主要对如电子邮件、信用卡、IP、Mac、url等进行脱敏，策略包括编辑、掩码、哈希、阻止等。
2. 检测并阻止提示注入攻击
3. 阻止不适当或有害内容
4. 强制执行业务规则和合规性要求
5. 验证输出质量和准确性

实现原理：通过中间件，在关键节点（agent执行前后、工具调用前后等）进行拦截处理。

#### 3.2.MCP

模型上下文协议 (MCP) 是一个开放协议，用于标准化应用程序向大型语言模型 (LLM) 提供工具和上下文的方式。

通过@mcp.tool自定义mcp服务。

```shell
pip install langchain-mcp-adapters
```

#### 3.3.multi-agent
agent间协同完成复杂任务。 agent间通过工具调用或者控制权交接实现任务执行。

实现原理：通过主agent控制各个子agent的执行

核心：上下文工程。需要控制的内容如下
1. 对话或状态的哪些部分传递给每个智能体。
2. 为子智能体量身定制的专用提示。
3. 包含/排除中间推理。
4. 为每个智能体定制输入/输出格式。


#### 3.4.检索-RAG

|架构	| 描述                            | 	控制 | 	灵活性 | 	延迟	 | 示例用例           |
|---|-------------------------------|-----|------|------|----------------|
|两步RAG| 检索总是在生成之前发生。简单且可预测            | ✅高  | ❌低   | ⚡ 快  | 常见问题解答、文档机器人   |
|代理式RAG| 一个由 LLM 驱动的代理决定在推理过程中何时以及如何检索 | ❌低  | ✅高   | ⏳可变  | 可访问多种工具的研究助手   |
|混合| 结合了两种方法的特点，并带有验证步骤            | ⚖️中 | ⚖️中  | ⏳可变  | 带有质量验证的领域特定问答  |

#### 3.5.Studio
Studio 是langchain提供的免费、强大的代理 IDE，它与 LangSmith 集成，可实现跟踪、评估和提示工程。
精确查看您的代理如何思考，跟踪每一个决策，并发布更智能、更可靠的代理。

#### 3.6.集成测试
LangChain提供的AgentEvals通过执行**轨迹匹配**或使用**LLM 判断器**实现智能体的轨迹的评估（确切的消息序列，包括工具调用）。

```shell
pip install agentevals
```
1. 轨迹匹配评估器。AgentEvals 提供了 create_trajectory_match_evaluator 函数，用于将您的智能体轨迹与参考轨迹进行匹配。
2. LLM-as-Judge 评估器。可以使用 LLM 和 create_trajectory_llm_as_judge 函数来评估智能体的执行路径。与轨迹匹配评估器不同，它不需要参考轨迹，但如果可用可以提供。
3. 异步支持。所有 agentevals 评估器都支持 Python asyncio。对于使用工厂函数的评估器，通过在函数名中的 create_ 后面添加 async 即可获得异步版本。

#### 3.7.LangSmith 集成

为了跟踪随时间变化的实验，您可以将评估器结果记录到 LangSmith，这是一个用于构建生产级 LLM 应用程序的平台，包括跟踪、评估和实验工具。

LangSmith 提供两种主要的评估方法：pytest 集成和 evaluate 函数。
