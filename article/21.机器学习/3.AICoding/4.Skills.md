- skills官网：[https://agentskills.io/home](https://agentskills.io/home)

## 基础

### 1.介绍
Claude Skills是Anthropic推出的一套基于提示词的模块化能力扩展系统。

基于提示词的动态上下文注入与元工具架构。与传统观念不同，Skill并非让模型调用外部函数，而是将领域特定的指令、工作流和知识"展开"并"注入"到对话上下文中。

本质：一组 prompt / workflow / 工具链配置

作用：
- 渐进式披露: 降低模型"降智"风险
- 工作流统一: 减少代码结构幻觉
- 架构完整性: 保证需求+功能逻辑性

### 2.安装技能

claude默认支持。在.claude根目录的就是全局skills，安装在项目根目录的就是项目级别的skills。

目前所有的AI编程工具都支持了。规则与claude一致。

### 3.内容结构

skills采用markdown格式编写。

```text
1. 目录结构
my-skill/
  ├── SKILL.md              # 核心提示模板
  ├── scripts/              # 可执行Python/Bash脚本
  │   ├── validator.py
  │   └── processor.sh
  ├── references/          # 参考文档
  │   ├── terminology.md
  │   └── examples.md
  └── assets/              # 模板和静态资源    
      ├── template.docx    
      └── config.json
      
2.SKILL.md文件结构：       
---
name: my-skill
description: 清晰描述技能功能和触发场景
allowed-tools: "Read,Write,Bash"
---

# 技能详细指令

## 工作流程
1. 第一步说明
2. 第二步说明
3. 第三步说明

## 输出规范
- 格式要求
- 质量要求
- 示例输出
```

### 4.与MCP对比

1. MCP：决定干什么。例如查询数据库
2. skills：决定怎么干。例如使用什么SQL查询数据库。

### 6.CI/CD相关
- frontend-code-review。前端代码审查相关，langgenius 提供。
    - 地址：https://github.com/langgenius/dify
    - 作用：自动化审查前端代码（.tsx/.ts/.js），从代码质量、性能表现、业务逻辑等维度进行分析。
    - 亮点：生成结构化审查报告，分“紧急待修复”和“改进建议”两类问题，标注文件路径、行号及修复方案。
    - 使用场景：审查待提交的变更（git commit 前）；审查指定文件（重构/优化前）；获取结构化修复报告。
- code-reviewer。全栈代码与 PR 审查相关，google-gemini 提供。
    - 地址： https://github.com/google-gemini/gemini-cli
    - 作用：支持本地代码改动和远程 PR 审查，保障代码正确性、可维护性、符合项目规范。
    - 亮点：审查维度全面，包括正确性、可维护性、可读性、效率、安全性、测试完整性。
    - 使用场景：审查远程 PR（提供 PR 编号/URL，AI 自动 checkout 代码运行检查脚本）；审查本地代码变更；深度代码分析。
- code-reviewer：来源：davila7/claude-code-templates
    - 多语言代码审查全能助手，弥补人工审查效率低、跨语言知识盲区的痛点。支持 TS/JS/Python 等主流语言，从质量、安全、性能多维度深度分析，
    - 生成带优先级的审查清单与修改示例。适用于小团队 PR 审查、技术债务清理，安装插件后指令调用即可使用。
- code-review-graph。用 Tree-sitter 把代码解析成结构图谱（函数、类、调用链、依赖关系），存本地 SQLite。
  - 每次文件变更，只更新受影响的部分。 核心是"爆炸半径"分析： 改了一个函数，自动追踪所有调用方、依赖方、关联测试。 AI 只读它需要读的文件。
  - [code-review-graph：Claude Code 本地知识图谱，减少 6.8 倍代码审查 Token !](https://mp.weixin.qq.com/s/jc5RZB9eIYSAmEUMfMxtkg)
  - 安装：pip install code-review-graph
- fix。代码格式化与规范检查相关，facebook 提供。
    - 地址：: https://github.com/facebook/react
    - 作用：自动执行 yarn prettier（格式化）与 yarn lint（检查规范错误），确保代码符合项目规范以顺利通过 CI/CD。
    - 亮点：集成格式化与规范检查于一体，预防代码风格问题导致的 CI 失败。
    - 使用场景：提交代码前的预防性检查；修复已发现的 linting 或格式问题；解决 CI 失败问题。
- pr-creator。自动化 PR 创建相关，google-gemini 提供。
    - 地址：https://github.com/google-gemini/gemini-cli
    - 作用：自动化创建高质量 PR，遵循项目模板与质量检查标准，提升代码审查效率。
    - 亮点：一键创建符合规范的 PR，引导新贡献者完成首次代码提交，自动执行创建 PR 前的质量检查（preflight 脚本）。
    - 使用场景：一键创建符合规范的 PR；引导新贡献者完成首次代码提交；自动执行创建 PR 前的质量检查。
- update-docs。自动化文档更新相关，vercel 提供。
    - 地址： https://github.com/vercel/next.js
    - 作用：根据源代码变更自动分析、更新和创建文档，确保代码和文档同步，为 PR 审查时的文档完整性检查设计。
    - 亮点：自动关联代码变更与文档更新，支持更新现有文档（props 表格、代码示例、废弃通知等）及为新功能创建脚手架文档。
    - 使用场景：分析代码变更对文档的影响；更新现有文档；为新功能创建脚手架文档。

工作原理:graphify 分两轮执行。
1. 第一轮是确定性的 AST 提取，对代码文件做结构分析（类、函数、导入、调用图、docstring、解释性注释），这一轮不需要 LLM。
2. 第二轮会并行调用 Claude 子代理处理文档、论文和图片，从中提取概念、关系和设计动机。
   最后把两边结果合并到一个 NetworkX 图里，用 Leiden 社区发现算法做聚类，并导出成可交互 HTML、可查询 JSON，以及一份人类可读的审计报告。
   - 聚类是基于图拓扑完成的，不依赖 embeddings。 
   - Leiden 按边密度发现社区。
   - Claude 抽取出的语义相似边（semantically_similar_to，标记为 INFERRED）本来就存在于图中，所以会直接影响社区划分。
   - 图结构本身就是相似性信号，不需要额外的 embedding 步骤，也不需要向量数据库。

每条关系都会被标记为 EXTRACTED（直接在源材料中找到）、INFERRED（合理推断，并附带置信度分数）或 AMBIGUOUS（有歧义，需要复核）。
所以你始终知道哪些是实际发现的，哪些是模型猜出来的。

/graphify ./raw --mcp              # 启动 MCP stdio server

# git hooks - 跨平台，在 commit 和切分支后重建图谱
graphify hook install
graphify hook uninstall
graphify hook status

# 增量更新

graphify update ./src                        # re-extract code files, no LLM needed
graphify cluster-only ./my-project           # rerun clustering on existing graph.json

输出：
1. graph.html——可交互的图谱可视化，点击节点、搜索、按社区筛选
2. GRAPH_REPORT.md——纯文本审计报告，列出核心节点、意外关联和建议问题
3. graph.json——持久化的图谱数据，几周后再查也不需要重读原始文件

## 最佳实践

### 1.第一性原理

真的AI Agent的行为约束。将其放入全局的Claude.md或者Agent.md文件中，提升vibe coding的效果和质量。

```markdown
- 约束1：先列计划，批准再动手。开始任何任务前，先列出你的执行步骤并等待明确批准。计划未经确认，不得开始实施。
- 约束2：改之前先读文件。编辑任何文件之前，必须先读一遍。
- 约束3：别重复造轮子。尽量缩小改动范围，优先复用项目已有的抽象和函数，绝对禁止将代码重新穿透多层调用链实现一遍。
- 约束4：不确定先说，不要猜。如果没有可参考的先例，停下来问，不要自己发明需求，那是人类的工作。
- 约束5：中途转向，先问再动。实施可能影响用户的改动前，先确认方案。如果范围发生变化，重新制定计划。
- 约束6：计划外的问题先报告。遇到与当前任务无关的废弃代码或可疑行为，说出来，严禁自己动手。
- 约束7：改了什么必须汇报。提交之前，把完整的改动差异展示给用户，并获得明确批准。
- 约束8：没跑过测试不算完成。在宣布实现就绪前，针对改动的包跑一遍能覆盖lint、类型检查和测试失败的最小验证。
```

## 企业落地

### 1.skills落地难题
1. 安全挑战：恶意代码、已知漏洞、敏感信息外泄风险持续存在，缺乏有效的准入管控机制。
2. 权限挑战：谁可见、谁可用、谁可改、谁可发——职责边界模糊，越权访问难以防范。
3. 稳定性挑战：版本混乱、升级不可控、问题难以回滚，影响业务连续性。
4. 治理挑战：缺少审计日志、追溯链条不完整、缺乏合规证据链，无法通过监管审查。
